## Roadmap (revised 2026-11-10; full version in `notes/roadmap.md`)
Goal: a stationary K1 that holds a spoken conversation on the real robot, gesturing in sync with its speech; later an LLM companion that also calls skills (walk_to, look_at, point, wave). Priority: a working system first; a paper is a bonus (likely angle: K1-native streaming generator). Plan without hands. Layered stack, the LLM never controls joints: mics → STT → LLM (+ tool calls) → TTS → gesture generator → **50 Hz K1 reference stream** (the stable contract; legs on a fixed standing reference) → **RL tracker (onboard)**. GMR stays offline (library / training data). Locomotion via Booster's SDK at first.
1. Hardware, canned clips (first session Thu 2026-11-12; also: SDK arms while Booster holds the legs? K1 mics with motors on, network delay).
2. Generated-motion smoke test: EMAGE offline (it can't stream) → GMR → `eval-tracking` / `sim2sim`.
3. **Retrieval generator v0 in sim (main work now; `notes/gesture_plan.md`):** TTS WAV → matched BEAT2 K1 clips, crossfaded → dubbed `sim2sim` video + 2-min continuous run. Streaming (`gesture live`) built 2026-11-11.
4. Final tracker run: exit criteria incl. observation history (experiment: `history_length` 10) and 10-min continuous operation. Table in `notes/roadmap.md`.
5. Speech (`notes/speech_plan.md`): steps 1–4 done incl. streaming (2026-11-11), paused; next barge-in (step 5). 6. Live on the robot. 7. LLM tool calls. 8. Neural generator if retrieval is repetitive, then mobility + presenting.

Data: BEAT2 (SMPL-X + audio) is the tracker's main training data. AMASS waves/points kept for semantic gestures. Missing gestures: phone video → GVHMR → GMR.

K1 constraints: ~0.95 m, 22 DoF; head 2 (yaw, pitch), arms 4 each (shoulder ×3, elbow), legs 6 each. **No wrists, no waist, no hands** (hardware group is building hands).

## Environment gotchas
- WandB entity must be the **team**: `WANDB_ENTITY=bmcox2-university-of-illinois-urbana-champaign` (not `bmcox2`, not the `-org` name). Set in `~/.bashrc`.
- Hardware: Dell XPS 15, RTX 4070 Laptop 8 GB, Ubuntu 24.04 (dual boot). GPU power capped ~35 W; dGPU has dropped out intermittently and the laptop has overheated before. Check `nvidia-smi` before runs; stop if GPU sustains >~87 °C. Prefer the club GPU for long runs.
- **`nvidia-smi` fails after a kernel update** (2026-10-19): the NVIDIA module package wasn't updated with the kernel, so the GPU runs with no driver, stuck at full power (loud fans at idle). Fix: `sudo apt install linux-modules-nvidia-595-open-generic-hwe-24.04` then reboot. Use `sudo apt full-upgrade` for kernel updates.
- **dGPU dropouts are hardware** (journal analysis 2026-10-19): every failure is the PCIe link failing to come back when the GPU powers up (`pcieport 0000:00:01.0: retraining failed` → Xid 79 / `GSP boot failed at resume`), after suspend or runtime power-off. Sometimes it also fails at cold boot, and then the BIOS hides the GPU for days (09-09→10-02, 10-16→10-18). It never failed under load. Don't disable runtime power-off (`NVreg_DynamicPowerManagement=0x00`) to avoid this: the awake GPU idles at ~25 W at P8 (fans ~5,000 RPM); tried and reverted 2026-10-19. Mitigations kept: lid close → power off (`/etc/systemd/logind.conf.d/lid-poweroff.conf`), no auto-suspend on battery. To override `/lib/modprobe.d/nvidia-runtimepm.conf` (`0x02`), a file in `/etc/modprobe.d/` must have the **same name**, then `update-initramfs -u`. Check the live value with `grep DynamicPower /proc/driver/nvidia/params`.
- 4096 envs fits in 8 GB (~3k iterations ≈ 2.5 h for the velocity task).
- SSH to the **club GPU PC** (`sigrobotics`, x86, not the robot): `ssh booster@10.193.169.55` (private campus IP, so it only works on the campus network or VPN). The K1's own address: not known yet (ask the lead); `sync_to_robot.sh` needs `ROBOT=<user>@<k1-ip>`.
- **Resume training:** add `--agent.resume True` with `--wandb-run-path <entity>/mjlab/<run> --wandb-checkpoint-name model_N.pt`, or it silently starts from scratch. `--agent.max-iterations` = additional iterations. Run long jobs on the club GPU inside `tmux` (`tmux new -s train`, detach `Ctrl-b d`).
- **WandB conventions:** name runs `MM-DD what-it-is`, tag them (`tracking`, `general`, `beat2`, `keep`/`superseded`...), one-line result note; dataset versions get a description, and the `current` alias moves to the version in use.
- Club GPU WandB: shared `booster` account, so no `wandb login`. Run `source ~/bmcox2/.wandb_env` in each new shell before `uv run train` / `eval-tracking` / `play`.
